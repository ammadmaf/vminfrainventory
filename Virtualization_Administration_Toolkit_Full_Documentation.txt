1. WHAT THIS TOOLKIT IS
========================================================================

The Virtualization Administration Toolkit is a Python-based infrastructure reporting
and administration project. It has two major parts:

1. Excel workbook generator
   - Creates a professional Virtualization administration workbook named:
     output/Premium_Virtualization_Administration_Toolkit.xlsx
   - Uses Python and openpyxl.
   - Builds a multi-sheet workbook for VM inventory, hosts, datastores,
     capacity planning, snapshots, backups, licensing, reference data,
     instructions, and an executive dashboard.
   - Includes sample enterprise virtualization data, formulas, dropdowns,
     conditional formatting, charts, workbook styling, and navigation tiles.

2. Flask web console
   - Runs a browser-based administration console at:
     http://127.0.0.1:5000
   - Uses SQLite for persistence.
   - Lets users view and add VMs, hosts, datastores, VLANs, backup jobs,
     clusters, and users.
   - Provides dashboard metrics, permission-controlled actions, protected
     delete rules, live dropdowns, and an Excel export button.

The project is designed for virtualization administrators, infrastructure engineers,
managed service providers, consultants, IT operations teams, and organizations
that need structured virtualization documentation and reporting.

The toolkit is not a direct replacement for management server, Host, or Virtualization Aria. It
is an inventory, governance, reporting, and workbook-generation system. It
does not connect to management server automatically in the current code. Instead, it
uses sample data, manually entered data, and SQLite-backed web records.

4. HOW TO RUN IT
========================================================================

Create and activate a Python virtual environment:

python -m venv .venv
.\.venv\Scripts\Activate.ps1

Install dependencies:

pip install -r requirements.txt

Run the Excel workbook generator:

python main.py

Expected output:

output/Premium_Virtualization_Administration_Toolkit.xlsx

Run the web console:

Set these values before the first run of a new database:

VIRTUALIZATION_TOOLKIT_SECRET_KEY
VIRTUALIZATION_TOOLKIT_ADMIN_PASSWORD
VIRTUALIZATION_TOOLKIT_CLIENT_PASSWORD

python web.py

Open this URL:

http://127.0.0.1:5000

Recommended production environment variables:

VIRTUALIZATION_TOOLKIT_SECRET_KEY
Purpose: Flask session signing secret.
Default in development: process-local random value.
Production recommendation: set this to a long persistent random secret.

VIRTUALIZATION_TOOLKIT_ADMIN_PASSWORD
Purpose: initial admin user password.
Required before first database initialization.

VIRTUALIZATION_TOOLKIT_CLIENT_PASSWORD
Purpose: initial client user password.
Required before first database initialization.

Docker build:

docker build -t virtualization-administration-toolkit .

Docker run:

docker run -p 5000:5000 ^
  -e VIRTUALIZATION_TOOLKIT_SECRET_KEY="replace-with-a-secure-secret" ^
  -e VIRTUALIZATION_TOOLKIT_ADMIN_PASSWORD="replace-with-admin-password" ^
  -e VIRTUALIZATION_TOOLKIT_CLIENT_PASSWORD="replace-with-client-password" ^
  virtualization-administration-toolkit

For persistent data in Docker, mount /app/instance to a persistent volume.

5. SECURITY, ROLES, AND PERMISSIONS
========================================================================

Authentication:
- Users sign in through /login.
- Passwords are stored as Werkzeug password hashes.
- Successful login stores user_id in the Flask session.
- Logout clears the session.

Built-in roles:

admin:
- Superuser.
- Automatically has every permission.
- Permission checkboxes appear checked and disabled in the users table.
- Can create resources, delete resources, export workbook, and manage users.

client:
- Read-only by default.
- Can view dashboard and resource tables.
- Cannot create, delete, export, or manage users unless permissions are
  explicitly granted.

Assignable permissions:

resource.create
- Label: Create resources.
- Description: Create VMs, hosts, datastores, VLANs, backup jobs, and clusters.
- Controls visibility and server access for Add buttons and POST resource APIs.

resource.delete
- Label: Delete resources.
- Description: Delete resources when dependency protection allows it.
- Controls delete buttons and DELETE resource APIs.

workbook.export
- Label: Export workbook.
- Description: Download the premium Excel workbook from the web console.
- Controls the Export Excel button and /export/workbook route.

users.manage
- Label: Manage users.
- Description: Create users and assign or revoke permissions.
- Controls Add User, permissions table, and user API routes.

Server-side enforcement:
- Permissions are enforced in Flask route decorators.
- Hidden UI alone is not relied on for security.
- Unauthorized API attempts return:
  {"message": "You do not have permission."}
  with HTTP 403.

Audit events:
- Create resource, delete resource, create user, and permission update actions
  are written to the audit_events table.
- Stored fields: actor, action, entity_type, entity_name, created_at.

Storage Utilization:
- Shows percentage of used datastore capacity.
- Formula in service layer:
  storage_used_percent = SUM(used_gb) / SUM(capacity_gb) * 100
- Shows used GB and total capacity GB.
- Uses a horizontal meter.

Power State:
- Live distribution of power_state values.
- Shows each category count and percentage.

Environment:
- Live distribution of VM environment values.
- Usually Production, Development, Test, DR, etc.

Operating System:
- Groups operating systems into Windows, Linux, and Other.

- Groups VMs into Enabled and Disabled based on backup_enabled.

Criticality:
- Groups VMs by criticality, such as Critical, High, Medium, Low.

Datastore Utilization:
- Lists up to 8 datastores ordered by used percentage descending.
- Shows used GB, capacity GB, and percentage.

Operational Warnings:
- Shows prioritized warnings from the service layer:
  - Datastores above 80%.
  - VMs with snapshots.
  - Outdated Guest Tools.
  - Backups disabled.
  - Critical VMs.
- If none exist, shows "No active governance warnings".

Governance Model:
- Static guidance list shown in the dashboard:
  - Dropdowns read live hosts, clusters, datastores, VLANs, and backup jobs.
  - Admin users are superusers with all permissions.
  - Client users are read-only until rights are assigned.
  - User permissions can be granted or revoked in Admin.
  - Assigned resources return a protected-delete warning.

Recent Virtual Machines table:
- Shows up to 8 most recently inserted VMs.
- Columns:
  - VM Name.
  - Environment.
  - Power.
  - Criticality.
  - Host.
  - Datastore.

Dashboard refresh:
- JavaScript calls /api/summary.
- Updates KPI text, storage meter width, distributions, warnings, and recent VM

- VMs through vms.datastore_id.

- VMs through vms.vlan_id.

- No delete guard.
- Can be deleted directly when user has resource.delete.

- HTTP 409.
- Message format:

33. IMPORTANT LIMITATIONS AND NOTES
========================================================================

Current implementation limitations:
- The toolkit does not currently connect directly to Virtualization management server APIs.
- Web console data and workbook sample data are separate systems.
- Export workbook regenerates the static/sample workbook from code, not a
  workbook built from current SQLite web-console records.
- No edit/update form is implemented for existing resources.
- Delete exists, create exists, list exists, but update existing resource
  fields is not implemented.
- No password reset page is implemented.
- No audit log page is currently visible in the UI.
- No pagination or search is implemented for large web tables.
- Client-side permission hiding improves UX, but server-side route checks are
  the real access control.
- SQLite is suitable for local or simple deployment, but production multi-user
  deployments may require stronger database planning.

Strong future improvement ideas:
- Add management server import using platform APIs such as Virtualization, Proxmox, Hyper-V, or KVM integrations.
- Connect workbook export to live SQLite records.
- Add edit forms for VMs, hosts, datastores, VLANs, backup jobs, clusters, and
  users.
- Add audit log page.
- Add search, filtering, and pagination in the web console.
- Add CSRF protection for form and API actions.
- Add stronger password policy and password rotation.
- Add role templates beyond admin/client.
- Add backup/restore for SQLite database.
- Add unit tests for service permissions and protected delete rules.
- Add validation for IP address, CIDR, capacity ranges, and duplicate names
  before API submission.

34. SHORT SUMMARY
========================================================================

The Virtualization Administration Toolkit is a combined reporting workbook generator
and Flask web console for virtualization-style infrastructure administration. The Excel
side produces a polished, formula-driven, multi-sheet workbook for inventory,
capacity, snapshots, backups, licensing, and executive reporting. The web side
provides a governed resource console with login, roles, permissions, dashboard
metrics, live dropdowns, create forms, delete protection, and workbook export.

It is best understood as an enterprise documentation and reporting starter
kit: useful for creating structured virtualization inventory records, presenting
executive summaries, managing reference data, and enforcing simple governance
rules around assigned infrastructure resources.

35. END-TO-END WEB CONSOLE DATA FLOW
========================================================================

This section explains exactly what happens from login through dashboard
refresh and resource creation.

Startup flow:
1. web.py imports create_app from webapp.
2. create_app builds a Flask application.
3. Flask config is loaded:
   - SECRET_KEY from VIRTUALIZATION_TOOLKIT_SECRET_KEY or a process-local random value.
   - DATABASE_PATH set to virtualization-toolkit/instance/toolkit.sqlite3.
   - PROJECT_ROOT set to the virtualization-toolkit folder.
4. init_database(app) runs.
5. instance folder is created if missing.
6. SQLite schema is created if missing.
7. Permissions are seeded.
8. Admin and client users are seeded.
9. Demo infrastructure data is seeded.
10. Request hooks are registered.
11. Routes are registered.
12. App serves on 127.0.0.1:5000 in local debug mode.

Request hook flow:
1. Before each request, load_logged_in_user runs.
2. It checks session["user_id"].
3. If no user_id exists, g.user remains None.
4. If user_id exists, users table is queried.
5. g.user becomes a plain dictionary.
6. Explicit permissions are loaded from user_permissions.
7. g.user["permissions"] becomes a sorted list.

Login flow:
1. Browser opens /login.
2. User submits username and password.
3. Flask queries users table by username.
4. Werkzeug checks the password hash.
5. If valid:
   - session is cleared.
   - session["user_id"] is set.
   - browser redirects to /.
6. If invalid:
   - login page re-renders.
   - flash error is shown.

Dashboard page load flow:
1. Browser requests /.
2. login_required confirms g.user exists.
3. get_dashboard_summary builds initial summary data.
4. list_permissions fetches permission catalog.
5. dashboard.html renders:
   - body data-role.
   - body data-superuser.
   - body data-permissions.
   - initial summary values.
   - nav and views.
6. app.js loads after HTML.
7. DOMContentLoaded fires.
8. refreshPermissionControls hides controls user cannot use.
9. Navigation event handlers bind.
10. Modal open/close handlers bind.
11. refreshAll starts.

refreshAll JavaScript flow:
1. Calls refreshReferences.
2. refreshReferences GETs /api/reference-options.
3. If user has users.manage, GET /api/permissions.
4. Loads all resources in parallel:
   - clusters.
   - hosts.
   - datastores.
   - vlans.
   - backup_jobs.
   - vms.
   - users only if users.manage.
5. Each resource result is stored in state.resources.
6. Each table is rendered.
7. refreshSummary GETs /api/summary.
8. KPI values, charts, storage meter, warnings, and recent VM table update.

Create resource flow:
1. User clicks an Add button.
2. Button must be visible, which requires resource.create or users.manage.
3. openModal(type) refreshes reference options first.
4. Modal fields are generated from modalDefinitions.
5. User fills fields and clicks Save.
6. submitResource converts FormData to a JSON object.
7. JavaScript POSTs to the endpoint for that resource.
8. Flask checks login.
9. Flask checks required permission.
10. Service function validates resource type.
11. Resource-specific create function inserts row.
12. Audit event is inserted.
13. Database commits.
14. Created row is returned.
15. Modal closes.
16. Toast confirms creation.
17. refreshAll reloads references, resources, and dashboard summary.

Delete resource flow:
1. User clicks Delete on a row.
2. Delete button appears only if user has resource.delete.
3. JavaScript sends DELETE to /api/resources/<resource>/<id>.
4. Flask checks login and permission.
5. delete_resource validates the resource name.
6. If the resource is vms:
   - delete proceeds directly.
7. If the resource is not vms:
   - assignment blockers are checked.
8. If blockers exist:
   - service returns deleted=False.
   - HTTP status is 409.
   - message explains dependency count.
9. If no blockers:
   - row is deleted.
   - audit event is written.
   - database commits.
10. JavaScript shows success or error toast.
11. On success, refreshAll reloads the UI.

Permission update flow:
1. Admin opens Admin page.
2. Users table renders one checkbox per permission per user.
3. Admin users have disabled checkboxes because admins are superusers.
4. Client users have editable checkboxes.
5. Changing a checkbox calls updateUserPermissions(userId).
6. JavaScript collects all checked permission codes for that user.
7. JavaScript sends PUT /api/users/<id>/permissions.
8. Flask checks users.manage.
9. Service validates target user exists.
10. Service validates every permission code exists in permissions table.
11. Old explicit permissions for user are deleted.
12. New explicit permissions are inserted.
13. Audit event is written.
14. Database commits.
15. Toast confirms update.
16. Users table reloads.

Workbook export flow from web console:
1. User clicks Export Excel.
2. Button requires workbook.export.
3. Browser requests /export/workbook.
4. Flask checks login and permission.
5. VirtualizationAdministrationToolkit(PROJECT_ROOT) is created.
6. toolkit.run() regenerates the workbook.
7. send_file downloads the workbook as an attachment.

36. JAVASCRIPT STATE, ENDPOINTS, AND UI BEHAVIOR
========================================================================

Global state object:

state.role:
- Comes from document.body.dataset.role.
- Values are usually admin or client.

state.isSuperuser:
- True when body data-superuser is "true".
- Admin users get true.

state.permissions:
- Parsed from body data-permissions.
- Contains explicit permission codes for non-admin users.

state.activeView:
- Starts as overview.
- Updated when sidebar buttons are clicked.

state.referenceOptions:
- Filled by GET /api/reference-options.
- Used by reference dropdowns in modal forms.

state.resources:
- Holds loaded table data for clusters, hosts, datastores, VLANs, backup jobs,
  VMs, and users.

state.assignablePermissions:
- Loaded from GET /api/permissions only when the current user can manage users.
- Used to render permission columns in the users table.

Endpoint map:
- clusters -> /api/resources/clusters.
- hosts -> /api/resources/hosts.
- datastores -> /api/resources/datastores.
- vlans -> /api/resources/vlans.
- backup_jobs -> /api/resources/backup_jobs.
- vms -> /api/resources/vms.
- users -> /api/users.

Navigation behavior:
- Sidebar buttons have data-view attributes.
- Clicking a nav item:
  - Updates state.activeView.
  - Removes active class from all nav buttons.
  - Removes active class from all views.
  - Adds active class to clicked nav button.
  - Adds active class to matching view section.

Table rendering behavior:
- renderTable(resource) finds table by id:
  - table-vms.
  - table-hosts.
  - table-datastores.
  - table-vlans.
  - table-backup_jobs.
  - table-clusters.
  - table-users.
- Users table has custom rendering because it includes permission checkboxes.
- Other tables use tableColumns definitions.
- Delete action column appears only when hasPermission("resource.delete") is
  true.

Value formatting:
- health, status, power_state, criticality, and snapshot values are rendered
  as colored status pills.
- used_percent automatically appends percent sign.
- All values are escaped before insertion into HTML.

HTML escaping:
- Replaces:
  - & with &amp;.
  - < with &lt;.
  - > with &gt;.
  - " with &quot;.
  - ' with &#039;.
- This protects dynamic text inserted into HTML.

Dashboard chart rendering:
- renderDistribution renders label, count, percent, and a small bar.
- renderStorageRows renders datastore capacity usage bars.
- renderWarnings renders warning rows with severity class.
- renderRecentVms renders recent VM table rows.

Reference field rendering:
- Reference fields render as select dropdowns.
- First option is "Select <label>" with empty value.
- Choices come from state.referenceOptions[source].
- Choice label is displayed; id is submitted.

Host-to-cluster sync:
- In the Add VM modal, selecting host_id triggers syncClusterFromHost.
- JavaScript finds the selected host in referenceOptions.hosts.
- It reads the host.cluster string.
- It finds a matching cluster label in referenceOptions.clusters.
- It sets cluster_id to that matching cluster id.

Permission control refresh:
- refreshPermissionControls finds every element with data-required-permission.
- If current user lacks that permission, permission-hidden class is applied.
- permission-hidden sets display: none !important.

39. ERROR RESPONSES AND WHAT THEY MEAN
========================================================================

Invalid login:
- Page flash message:
  Invalid username or password.
- Meaning:
  Username was not found or password hash check failed.

Not logged in:
- Browser is redirected to /login for HTML pages.
- API routes are protected by login_required and will redirect if accessed as
  browser routes without session.

Missing permission:
- HTTP 403.
- Body:
  {"message": "You do not have permission."}
- Meaning:
  User is not admin and does not have the required explicit permission.

Unsupported resource:
- Usually HTTP 404 on list route or handled as error.
- Message:
  Unsupported resource: <resource>
- Meaning:
  Resource name is not in RESOURCE_TABLES.

Missing required field:
- HTTP 400.
- Message:
  Missing required field: '<field>'
- Meaning:
  Required JSON key was missing from payload.

Database rule failed:
- HTTP 409.
- Common reasons:
  - Duplicate unique name.
  - Foreign key issue.
  - Constraint violation.
- Example:
  Database rule failed: UNIQUE constraint failed: vms.name

Invalid role:
- HTTP 400.
- Message:
  Role must be admin or client.

Invalid permissions:
- HTTP 400.
- Message:
  Invalid permission(s): <codes>
- Meaning:
  Request tried to grant permission codes not present in permissions table.

Protected delete:
- HTTP 409.
- Message:
  <resource> is assigned to <dependency count> and must not be deleted.
- Meaning:
  Reassign or delete dependent resources first.

Resource not found:
- HTTP 404.
- Message:
  Resource not found.
- Meaning:
  Delete target id does not exist.

========================================================================
40. WORKBOOK FORMULA DETAILS BY SHEET
========================================================================

Executive Dashboard formula design:
- Dashboard formulas use full-column references against VM Inventory.
- This means the dashboard updates when users add rows anywhere in those
  columns.
- Excel recalculation is forced on open by workbook.calculation settings.

VM Inventory formula design:
- VM Inventory mostly stores direct values.
- Its governance comes from:
  - dropdowns.
  - reference dropdowns.
  - conditional formatting.
  - date/numeric formatting.
- It does not create formulas in core VM records.

Host Inventory formula design:
- Assigned VM Count is based on matching hostnames in VM Inventory.
- Deletion Status is based on Assigned VM Count.
- This mirrors the web app's protected delete idea inside Excel.

Datastore formula design:
- Free capacity and utilization are row-local formulas.
- Warning status derives from Percentage Used.
- Assigned VM Count checks VM Inventory Datastore column.
- Deletion Status warns when datastore is still assigned to a VM.

Capacity Planner formula design:
- Utilization formulas divide used by capacity.
- Forecast formulas apply growth percentage.
- Recommendation formula compresses multiple risk levels into one text output.
- Chart helper tables are placed to the right of the main table.

Snapshot Tracker formula design:
- Age uses TODAY, so it changes every day when Excel recalculates.
- Warning and Action Required are derived from age thresholds.
- Older snapshots automatically escalate from Healthy to 7+ Days, 14+ Days,
  30+ Days, and 90+ Days.

Backup Register formula design:
- Success % divides Successful Runs by Total Runs.
- Top KPI cards count job and status fields.
- Conditional formatting makes failed backups, weak success percentages, and
  failed restore tests visible.

License formula design:
- Available CPUs subtracts Used CPUs from Total CPUs.
- Status handles over-allocation first, then perpetual blank expiration, then
  expired, then active.

Reference Data formula design:
- Assigned Count formulas count usage in VM Inventory or Backup Register.
- Deletion Status converts counts into governance text.
- Defined names power validation dropdowns throughout the workbook.

========================================================================
41. WORKBOOK DROPDOWN GOVERNANCE MODEL
========================================================================

The workbook uses two dropdown types:

1. Fixed dropdowns:
- Options are hard-coded directly in data validation formulas.
- Good for stable categories like Power State or Criticality.

2. Reference dropdowns:
- Options come from workbook defined names such as RefHosts or RefClusters.
- Good for values that should be governed centrally.

Fixed dropdown examples:
- Power State.
- Criticality.
- Backup.
- Snapshot.
- Guest Tools.
- Health.
- Backup Status.
- Restore Test.

Reference dropdown examples:
- Host.
- Cluster.
- Datastore.
- VLAN.
- Backup Job.
- Repository.
- Owner.
- Business Unit.
- Security Zone.
- Support Group.

Why this matters:
- Users get controlled input lists.
- Reports become more consistent.
- Dashboard formulas count predictable values.
- Reference Data can warn when a value is still assigned.

43. TROUBLESHOOTING
========================================================================

Problem: Cannot log in with the admin account.
Possible causes:
- Database was already created with a different environment password.
- Password seed only inserts users if they do not already exist.
- You may need to update the database user password or delete/recreate the
  local instance database if this is only a demo environment.

Problem: Add buttons are missing.
Cause:
- Current user lacks resource.create or users.manage.
Fix:
- Log in as admin or grant the user the needed permission.

Problem: Export Excel button is missing.
Cause:
- Current user lacks workbook.export.
Fix:
- Log in as admin or grant workbook.export.

Problem: Delete buttons are missing.
Cause:
- Current user lacks resource.delete.
Fix:
- Log in as admin or grant resource.delete.

Problem: Delete button gives an error even though delete permission exists.
Cause:
- Resource is assigned to another resource.
Fix:
- Reassign or remove dependent VMs, hosts, or datastores before deleting.

Problem: A new host does not appear in Add VM dropdown.
Possible causes:
- Browser did not refresh references.
- Resource creation failed.
Expected behavior:
- Successful create calls refreshAll, so it should appear immediately.
Fix:
- Check toast messages.
- Refresh page.
- Confirm host exists in Hosts table.

Problem: Workbook dashboard numbers do not update in Excel.
Cause:
- Excel may not have recalculated yet.
Fix:
- Open workbook in Excel and recalculate formulas.
- The workbook is configured to force full calculation on load.

Problem: Web dashboard export does not include new web-console VMs.
Cause:
- Current export regenerates workbook from static workbook modules and sample
  data, not from SQLite resources.
Fix:
- This requires a future enhancement connecting workbook builders to database
  records.

Problem: Duplicate name error.
Cause:
- Many tables have unique name fields.
Fix:
- Use a new unique name or manually update/delete existing record.

Problem: Docker container loses data after rebuild.
Cause:
- instance folder was not mounted to persistent storage.
Fix:
- Mount /app/instance as a volume.

44. PRACTICAL ADMIN WORKFLOWS
========================================================================

Workflow: Create a new VM correctly.
1. Make sure the target cluster exists.
2. Make sure the target host exists and belongs to the cluster.
3. Make sure the target datastore exists.
4. Make sure the target VLAN exists.
5. Make sure the target backup job exists, if backup is enabled.
6. Open VM Inventory.
7. Click Add VM.
8. Enter VM Name and metadata.
9. Select Host.
10. Confirm Cluster auto-selects correctly.
11. Select Datastore.
12. Select VLAN.
13. Choose Backup Enabled and Backup Job.
14. Set Snapshot, Guest Tools, Power State, and Criticality.
15. Save.
16. Confirm VM appears in table.
17. Check Dashboard KPIs and warnings.

Workflow: Safely delete a datastore.
1. Open Datastores.
2. Check Assigned VMs count.
3. If count is 0, delete is allowed.
4. If count is above 0, identify assigned VMs in VM Inventory.
5. Delete or reassign those VMs first.
6. Try deletion again.

Workflow: Give a client export-only access.
1. Log in as admin.
2. Open Admin.
3. Create user with role client.
4. In Users & Permissions, check Export workbook.
5. Leave Create resources, Delete resources, and Manage users unchecked.
6. User can now view data and export workbook but cannot change resources.

Workflow: Give an operator create access but prevent deletes.
1. Log in as admin.
2. Open Admin.
3. Create or locate operator user.
4. Check Create resources.
5. Leave Delete resources unchecked.
6. Operator can add resources but cannot delete them.

Workflow: Full delegated administrator.
1. Log in as admin.
2. Create user with role admin.
3. Admin role automatically acts as superuser.
4. Permission checkboxes will show Superuser and cannot be changed.

48. FINAL DEEP SUMMARY
========================================================================

The project is best described as a commercial-quality virtualization operations
documentation starter kit. It contains both a generated Excel reporting
workbook and a browser-based resource console. The workbook side focuses on
offline reporting, formulas, charts, dropdown governance, and executive
visibility. The web side focuses on live resource entry, role-based access,
dashboard metrics, dependency protection, and exporting the workbook.

Every visible web page is represented in dashboard.html and controlled by
app.js. Every workbook sheet is represented by one Python builder module in
src. The service layer is the business-policy core of the web console: it
calculates metrics, validates permissions, creates resources, blocks unsafe
deletes, and writes audit entries.

The strongest current feature is the combination of governance ideas across
both interfaces: live web dropdowns from source tables, protected deletion in
the web app, reference lists in Excel, and deletion status warnings in the
workbook. The main limitation is that the exported workbook currently comes
from sample workbook builders, not from live SQLite records. Connecting those
two would make the toolkit a much more complete operational reporting system.
